# P1 复杂图片识别需求：心电图等专业图像

状态：**P1，已登记；不进入当前 MVP，尚未实现**


## 背景

当前 MVP 的照片范围是一张清楚的印刷资料照片，例如药盒、检查单或报告文字。心电图、超声图、CT/MRI 影像、病理切片和带曲线／波形的专业图像，不能按普通 OCR 处理后直接给老人结论。

这类图片可能同时包含波形、刻度、导联名称、设备参数、拍摄角度和纸面文字。只识别出部分文字，不能代表已经理解了图像，更不能据此自动诊断、改药或给出急救判断。

## MVP 边界

- MVP 不承诺心电图等复杂图片的自动识别或医学解读。
- MVP 可以保存原图（前提是媒体上传接口已经实现并确认保存成功）。
- 页面应显示“已保存原图，暂不支持复杂图像自动解读”，不能显示“识别完成”“AI 已看懂”或医学结论。
- 原图仍应进入患者档案，保留上传时间、来源和待处理状态，方便后续由家属或专业人员查看。
- 复杂图片不应被静默当作普通文档 OCR，也不能因为 OCR 返回少量文字就自动生成完整 Event。

## P1 目标

P1 只在媒体保存、来源追溯、普通印刷资料 OCR 已稳定后启动，目标是形成“识别结果可核对”的辅助能力，不替代医生诊断：

1. 判断图片类型：普通印刷资料、波形／曲线图、医学影像或无法判断。
2. 对心电图等波形图保留原图，并提取可验证的版面文字、导联标签、检查日期、设备参数；不从波形自动生成诊断结论。
3. 需要模型或专业规则时，输出机器初稿、来源区域和不确定项，要求人工核对后才能进入整理流程。
4. 当图像清晰度、角度、遮挡或格式不满足条件时，返回明确失败原因和重试建议，原图不丢失。
5. 对复杂图像和普通 OCR 结果分开标记，保留原件、识别尝试、人工修订和最终关联关系。

## 建议的 P1 处理流程

```text
上传原图 → 保存并校验 → 图片类型判断
  ├─ 普通印刷资料 → 普通 OCR → 危险扫描 → 生成待核对 Event
  └─ 复杂图像（心电图等） → 复杂图像识别任务
       → 原图 + 版面文字/参数初稿 + 来源区域 + 不确定项
       → 人工核对 → 再决定是否进入 Event 整理
```

复杂图像任务必须有独立状态，例如 `complex_pending / processing / succeeded / failed / needs_professional_review`。`succeeded` 只表示保存了可追溯的识别初稿，不表示诊断成功。

## 后续实现前提

复杂图片能力应先明确类型识别、来源区域、人工核对、错误恢复和支持范围，再更新 API 与类型合同。当前尚未实现，不扩大到公网医疗服务、自动诊断或处方建议。

## 验收证据要求

P1 合并时必须提供脱敏证据，至少包括：输入图像校验和、图像类型判断、原图保存状态、识别初稿摘录、来源区域、不确定项、人工对照、失败恢复和是否生成 Event。Mock 与真实服务分开标记；没有真实复杂图像服务证据时，状态保持“未验证”。
